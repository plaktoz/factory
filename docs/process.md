# How this repo is built

This file holds the rules for building the factory. They are different from what the factory does, which is in `docs/design/`. `AGENTS.md` is the short list every session reads. This file holds the why of each rule.

## Decisions

A row changes only through a new `proposed` ADR in `docs/adr/`. To read a folded ADR in full, see `docs/adr/README.md`; the Id cell is the file name without `.md`.

One fix pass, then report the scorecard. It is advice, not a gate. | It adds scorecards to agent work with no automation this repo lacks. | `revise-spec` runs `precheck.py` first. A problem about the scored file prints the problems and stops, with no scorecard. A problem elsewhere is a note. The skill never scores links, names, tick counts or records itself. | Each fault is reported once, where it is built to be reported. Never look at the checks. | 2026-11-21-revise-spec-runs-the-checks-first (D1, owner decision 2026-11-21) |
| The scorecard gives each dimension a whole score from 1 to 5. The lowest score sets the result: `ready` at 4 or more, `needs-changes` at 3, `rework` at 2 or less. No weights, no overall number. Ties are all named. | A strong dimension cannot hide a weak one. Weights let 5, 5, 3, 3 pass at 4.10, which contradicts the issue's own anchor for a 3. | A weighted total. A findings list with no scores. | 2026-11-21-scorecard-is-set-by-the-lowest-score (D2, owner decision 2026-11-21) |
| A score of 4 or 5 quotes the line that shows it, with its number. A score of 3 or less names the missing item and the line where it belongs. When unsure, give the lower score. A score with no evidence line is redone. | A reader can check any score by reading one line. The same ADR scored 3 on one run and 4 on the next. | A score with a remark and no quote. The median of three runs, at triple the cost. | 2026-11-21-scores-need-a-quote-or-a-named-gap (D4, owner decision 2026-11-21) |

The glossary row alone. | 2026-11-21-agents-rule-and-scorecard-glossary-row (D8, owner decision 2026-11-21) |
| A session takes the recommended option and keeps working. A finding a check can settle is fixed, with the check's output shown. A finding that needs a machine or a login becomes a task in `docs/tasks.md`; only what is left goes to the owner. (The 2026-11-14 rule these replace is `2026-11-14-decide-at-the-recommendation`.) Stop triggers: the choice reopens D1 to D14 or a row in a `Decisions` table, changes scope or phase, costs a lot to reverse, or has no clearly better option. Record by cost: a bug fix or upkeep, the commit message; a reversible choice, one line in `docs/decisions.md`; a stop trigger, an ADR and a card. Every decision-page card names its trigger, and the renderer refuses one without it. At most one decision page a day. Product before process until task item 12 is done. Owner decision, 2026-11-22. | The owner chose the recommended option about 95% of the time, so asking costs more than an undo. The old rule lived in an ADR, lost to a broader `AGENTS.md` rule, and held for 1 decision in 81. | Restate the 2026-11-14 rule more strongly. The owner decides everything, in batches. | 2026-11-22-decide-by-default-and-scale-the-record (owner decision 2026-11-22) |
| An ADR is a pending question. `docs/adr/` holds only `proposed` ADRs. The commit that accepts one folds its rule into the spec and deletes the file. Module rules go in a `Decisions` table. Repo-build rules go in this file. A one-off action or calibration round is not folded. Owner decision, 2026-11-22. | A file that is accepted and never edited cannot be kept up to date. An agent reads one module file, not 95 ADRs. Git keeps the full text. | A flat folder with an index. ADRs moved into component folders. | 2026-11-22-fold-accepted-adrs-into-the-specs (owner decision 2026-11-22) |
| A session does not edit `docs/tasks.md`. Its pull request body ends with a `## Task record` section, and whoever merges the pull request pastes it into the file in one commit on `main` and archives the oldest Log entries. | Since 2026-11-20, 125 commits touched the file and 15 of 86 merges conflicted in it, 13 in the Log or the "State at" paragraph, because git merges by line and one line is 8,027 characters. A single writer cannot conflict with itself. | One small file per Log entry (removes most clashes, but loses the single Resume page and changes the cap check). A git setting that keeps both sides (kept two copies of a clashing block in a test). Splitting every item into its own file (the largest rewrite; 14 files name the list). | 2026-11-22-owner-calls D1 integrator-writes |
| A session ends its turn only when it asks a question, lists what waits on the owner, or delivers a pull request. A progress update goes in the next message, and the session keeps working. Owner decision, 2026-11-23. | Over 66 sessions, 129 of 283 replies under 30 minutes (about 10 hours of gaps) came after a message that ended on a status update and asked nothing. The kind was read by keyword, so the split is an estimate. | Stop only when something waits on the owner (stricter, so a session must judge what waits and may run past a problem). Leave it (a status stop is a free check-in, but about 10 hours of gaps continue). | 2026-11-23-no-stop-on-a-status-update (retro finding F1, owner answer `keep-going-rule`) |
| A decision page holds at most five cards. Owner decision, 2026-11-23. | The owner took the recommendation in 71 of 89 answers (80%). Two batch days, 2026-11-21 and 2026-11-22, hold 64 of 99 answers, from pages of 8 cards. The triage step was not holding. | Leave it (many cards in one sitting can be efficient, but large batches keep arriving). | 2026-11-23-cap-a-decision-page-at-five-cards (retro finding F4, owner answer `triage-harder`) |
| Every pull request runs the four docs checks (`records.py`, `links.py`, `criteria.py`, `contracts.py`, about 3.4 s together) in a GitHub workflow, and the owner turns on "Allow auto-merge" and requires that check on `main`. | The end state is a factory that is autonomous within the owner's policy. The owner sets which repos, what may merge and what stays theirs; the factory decides everything else and reports. Owner decision, 2026-11-26. | The merge policy already grants autonomy one workflow at a time, and the owner can narrow a grant again. | Code runs the work and models do bounded jobs behind checks. A model never starts a task, moves a stage or merges. Autonomy rests on trusting the checks.
