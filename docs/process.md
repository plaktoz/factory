# How this repo is built

This file holds the rules for building the factory. They are different from what the factory does, which is in `docs/design/`. `AGENTS.md` is the short list every session reads. This file holds the why of each rule.

## Decisions

A row changes only through a new `proposed` ADR in `docs/adr/`. To read a folded ADR in full, see `docs/adr/README.md`; the Id cell is the file name without `.md`.

| Rule | Why | Not chosen | Id |
| --- | --- | --- | --- |
| The spec is markdown. There is no `.docx` copy. Diagrams are Mermaid blocks. Wireframes are text tables. A Word or PDF copy is made when needed and not committed. | Markdown diffs line by line and an agent can edit it. The docx was already behind, and two formats mean every change is made twice. | A `.docx` copy kept in step. | 2026-11-14-markdown-as-spec-format |
| The spec is split by module. `phase-1.md` is the overview. Each module has a file in `modules/`, shared sections are in `shared/`. Module numbers do not change. Cross-references are links. A fact lives in one file. | One file of 2,706 lines had to be loaded to read one contract. One file per module gives each builder one place and a small diff. | One single spec file. | 2026-11-14-one-file-per-module |
| A criterion that fails for a known gap is marked `xfail(strict=True)` with the gap named in the reason. The change that closes the gap removes the marker. Owner choice, 2026-11-16. | The test keeps running. A fix that passes it fails the suite until the marker is removed. A skip keeps one meaning: a missing tool. | `skip`: the test does not run, so a fix goes unnoticed. | 2026-11-16-strict-xfail-for-known-gaps (Q1 and Q2) |
| `pytest-xdist` (`>=3.8,<4`) is in the engine's dev group. `pytest -n <workers>` runs the suite in parallel. The default run stays serial. Owner instruction, 2026-11-21. | Measured on 10 cores: serial 388.6 s, `-n 8` 148.5 s, same tests passing. The dev group gives everyone the same setup. | Install it by hand in each environment. A separate optional group. | 2026-11-21-run-the-engine-suite-with-pytest-xdist |
| Pilot, set 2026-11-21. Rules stay in `AGENTS.md` as an Always, Ask first, Never table. A ticket's spec is its GitHub issue, filled in from an issue form. No `specs/` folder. | One rules file cannot drift from a second. The issue body reaches the worker. A per-ticket folder needs upkeep. | A `specs/` folder with a second rules file and a tasks file per ticket. | 2026-11-21-spec-rules-live-in-agents-md-and-issue-form (D2, owner decision 2026-11-21) |
| Pilot, set 2026-11-21. Follow the spec steps by hand on two medium tickets. The factory does nothing new. A later ADR decides whether to build the steps into a workflow. | Matches issue 56: pilot first. It costs a few lines and leaves the open phase 1a build alone. If the steps do not pay off, nothing is undone. | Build the steps into a feature workflow now. Adopt nothing. | 2026-11-21-spec-workflow-applies-by-hand-first (D1, owner decision 2026-11-21) |
| Pilot, set 2026-11-21. On work a person drives, a fresh agent session checks the diff against the acceptance list before the pull request. Factory runs keep their review as it is. | It costs one rule and no build. It keeps chores auto-mergeable. The factory already reviews where it matters most, in `bug-fix`. | A review stage in `chore`. It changes a shipped workflow and stops chores merging themselves. | 2026-11-21-adversarial-check-is-a-fresh-session-by-hand (D3, owner decision 2026-11-21) |
| Merge `origin/main` into the branch just before the push, and record the merge. At any other time, leave `main` alone. Owner decision, 2026-11-22. | It matches how earlier pull requests went in. A conflict is fixed where the records check runs. | Copy the commits onto a new branch from `main`. Push as is and let GitHub show conflicts. | 2026-11-22-merge-main-before-the-push (D3, owner decision 2026-11-22) |
| In the spec pilot, review time is the minutes from a pull request's opening to its merge, for the baselines and each ticket. Owner decision, 2026-11-22. | It is the only time measure that has a value for both baselines. Neither baseline has an approval. It cannot separate review from fixing time, so the day 14 note says so. | Minutes of the fresh-session check: no baseline. Defects only: one bug is the only signal. | 2026-11-22-measure-review-time-as-open-to-merge (D2, owner decision 2026-11-22) |
| `revise-spec` runs on request. Nothing runs it automatically. An `AGENTS.md` rule tells an agent to run it before it marks a design change or a `proposed` ADR done. One fix pass, then report the scorecard. It is advice, not a gate. | It adds scorecards to agent work with no automation this repo lacks. One pass stops an agent looping on its own score. | `AGENTS.md` rule left out. A run on every pull request. | 2026-11-21-revise-spec-runs-on-request (D3, owner decision 2026-11-21) |
| `revise-spec` runs `precheck.py` first. A problem about the scored file prints the problems and stops, with no scorecard. A problem elsewhere is a note. The skill never scores links, names, tick counts or records itself. | Each fault is reported once, where it is built to be reported. A narrow stop keeps the skill usable while an unrelated record is stale. | Score anyway after a failure. Never look at the checks. | 2026-11-21-revise-spec-runs-the-checks-first (D1, owner decision 2026-11-21) |
| The scorecard gives each dimension a whole score from 1 to 5. The lowest score sets the result: `ready` at 4 or more, `needs-changes` at 3, `rework` at 2 or less. No weights, no overall number. Ties are all named. | A strong dimension cannot hide a weak one. Weights let 5, 5, 3, 3 pass at 4.10, which contradicts the issue's own anchor for a 3. | A weighted total. A findings list with no scores. | 2026-11-21-scorecard-is-set-by-the-lowest-score (D2, owner decision 2026-11-21) |
| A score of 4 or 5 quotes the line that shows it, with its number. A score of 3 or less names the missing item and the line where it belongs. When unsure, give the lower score. A score with no evidence line is redone. | A reader can check any score by reading one line. The same ADR scored 3 on one run and 4 on the next. | A score with a remark and no quote. The median of three runs, at triple the cost. | 2026-11-21-scores-need-a-quote-or-a-named-gap (D4, owner decision 2026-11-21) |
| `AGENTS.md` carries the revise-spec rule under Working rules. The glossary in `phase-1.md` gets a Scorecard row: advisory, not a gate or an approval. The skill says "recommendation", not "status". | Agents learn when to run the skill. "Gate" and "approval" stay reserved for the engine's meaning. | The rule alone. The glossary row alone. | 2026-11-21-agents-rule-and-scorecard-glossary-row (D8, owner decision 2026-11-21) |
| A session takes the recommended option and keeps working. Stop triggers: the choice reopens D1 to D14 or an accepted ADR, changes scope or phase, costs a lot to reverse, or has no clearly better option. Record by cost: a bug fix or upkeep, the commit message; a reversible choice, one line in `docs/decisions.md`; a stop trigger, an ADR and a card. At most one decision page a day. Product before process until task item 12 is done. Owner decision, 2026-11-22. | The owner chose the recommended option about 95% of the time, so asking costs more than an undo. The old rule lived in an ADR, lost to a broader `AGENTS.md` rule, and held for 1 decision in 81. | Restate the 2026-11-14 rule more strongly. The owner decides everything, in batches. | 2026-11-22-decide-by-default-and-scale-the-record (owner decision 2026-11-22) |
| An ADR is a pending question. `docs/adr/` holds only `proposed` ADRs. The commit that accepts one folds its rule into the spec and deletes the file. Module rules go in a `Decisions` table. Repo-build rules go in this file. A one-off action or calibration round is not folded. Owner decision, 2026-11-22. | A file that is accepted and never edited cannot be kept up to date. An agent reads one module file, not 95 ADRs. Git keeps the full text. | A flat folder with an index. ADRs moved into component folders. | 2026-11-22-fold-accepted-adrs-into-the-specs (owner decision 2026-11-22) |
